# DutyRoute antislop audit 001

Scope: the existing React interface, source, responsive states and public deployment. The user requested both an audit and removal of slop, authorizing all fixes below. No optional skill installation or new visual assets are needed.

Design read: a dispatch tool for a solo property-carrying driver, using paper-log structure and restrained road-sign colors. ENERGY 2 / RHYTHM 2 / MOTION 1. Preserve the map, connected duty grid, ordered waypoints and real trip calculations.

## Findings

1. **HIGH, R-32:** The results use ARIA tab semantics but lack arrow-key navigation and a single tab stop. Focus outlines on schedule rows can be clipped by their container. Implement the keyboard pattern and visible inset row focus.
2. **MEDIUM, R-06:** Spaced uppercase eyebrows and schedule headers add a promotional hierarchy to ordinary task labels. Use sentence case and readable, compact metadata instead.
3. **LOW, R-05 / C-3:** “Plan the road ahead,” the three-part slogan and the empty-state welcome occupy space without helping a driver enter a trip. Replace them with a task heading and concrete search instructions; reduce the introductory spacing.
4. **LOW, R-31 / C-1:** The decorative L beside the wordmark adds a second motif unrelated to an actual route or duty record. Remove it and retain the real duty-line motif in the logs. The wordmark's bare hash link also offers no useful navigation in this single-screen tool; render it as text.
5. **LOW, R-15 / C-3:** “The complete trip” and “From departure to delivery” repeat what the results already show; every schedule row repeats “View on map.” Use “Trip results” and one shared instruction above the schedule.
6. **HIGH, R-32:** Map circles open useful popups with a mouse but are not keyboard controls. Give each a descriptive button name, visible focus, Enter/Space activation and Escape dismissal; make the route line noninteractive.
7. **HIGH, R-25:** Leaflet attribution links use blue over 80%-opaque white, making contrast depend on the underlying map. The minimum over a dark tile is 3.08:1. Use solid white and the app's teal links, guaranteeing 7.57:1.

## Retained with a purpose

- The three numbered circles represent the actual current, pickup and delivery order; they are not a generic three-step marketing section.
- Selected-location feedback is necessary because a typed query is not a geocoded selection.
- The four metrics use the same structure to compare measured distance, driving time, elapsed time and log count.
- Safety assumptions, estimated-stop notices and unsigned-log labels describe actual model limits.
- Teal route lines and amber rest/fuel pins explain geographic data. The printable four-row grid matches the supplied paper-log format.
- Code comments and docstrings describe the scheduling model; no filler comments require removal. The redundant direction-string no-op can be removed without changing behavior.
